# 总体架构 —— 现券询价谈价机器人(v1.0 重设计)

## 0. 定位(v1.0 目标,别再用成交率考核)

机器人**不追成交**,只做两件:**收窄 bid-offer 价差**、**拿到对方实价**;拿到实价即转人工。核心指标 = 实价获取率 / 价差收窄幅度 / 人工节省 / 无应答率。

## 1. 通道演进(三次转向,必须讲清)

| 阶段 | 通道 | 结论 |
|---|---|---|
| ① 初版 | QQ NapCat/OneBot(bondtrade demo) | 协议对接,谈价核心引擎已实现 |
| ② 0914 转向 | 邮件网关 + 外网PC RPA 抓 QT / 或 ODS 直连报价数据 | QT 无障碍控件读不出,外网PC RPA 独占易挂;转"工作台直连报价原始数据" |
| ③ 本次转向 | **redroid 跑企点 APK + RPA(frida 读 + adb 写)** | 把**聊天传输层**换成可控的 Android 容器,替掉外网PC RPA |

**关键澄清:两条线互补,不是替代**
- **数据线(ODS/财汇/中债)**:把 债券主数据 + 报价行情 + 估值 实时喂进工作台(屏1 行情、屏2 监控、屏3 问答的底料)。与聊天无关。
- **传输线(redroid RPA)**:机器人在企点上与对手方收发消息。替代 NapCat / 外网PC RPA。
两条线在**业务层(session)汇合**:数据线提供"该报什么价/边界/量",传输线负责"把话发出去、把回复读回来"。

## 2. 分层架构

```
┌─ 交互层(内网工作台,三屏) ────────────────────────────┐
│  意向询价 / 机器人监控(会话视图+同页发送) / 智能问答     │
└───────────────▲───────────────────────▲────────────────┘
                │ REST/WS                │
┌─ 业务层(session 引擎) ─────────────────────────────────┐
│  归属路由 L1-L5 · 谈价状态机 · 规则引擎(比大小/让步/边界) │
│  跨日续谈 · 转人工 · 话术模板 · 合规红线 · 全量留痕        │
└───────▲────────────────────────────────▲───────────────┘
   数据线 │                          传输线 │
┌─ 数据层 ───────────────┐   ┌─ 传输层(redroid RPA) ──────┐
│ 财汇:债券/发行人主数据  │   │ 企点 APK(redroid 容器)      │
│ 中债:估值/久期/隐含评级 │   │ frida 读 + adb UI 写         │
│ QT/OT:报价行情/筛券     │   │ 状态机+会话括号+双闸门(04)   │
│ Oracle:授信额度        │   │ 前期验证 QQ,生产 QT         │
│ 机构库:对手/发行人识别  │   └─────────────────────────────┘
└────────────────────────┘
```

模型只在业务层的一个点出现:**意图分类 + 结构抽取(dify,见 06)**。比大小、让不让、停不停,一律规则引擎(存款项目教训:中文歧义大,比大小绝不给模型)。

## 3. 内外网切分与提速(需求 12 章)

现有链路一次"发一轮+收回复" = 两次邮件穿透 + 两次轮询,单轮 5 分钟起。redroid RPA 若与外网侧同处一网段,可去掉"外网PC RPA 抓屏"这段脆链,但**内外网穿透仍在**(工作台在内网,redroid/企点在外网)。

**最大杠杆:策略引擎下沉外网**——发起时一次性下发策略,机器人在外网自主跑完中间轮次,只在"发起"与"转人工"两刻穿透。往返从"每轮 2 次"降到"整单 2 次"。三档:

| 档 | 外网持有 | 建议 |
|---|---|---|
| A 全下沉 | 起始/边界/步幅/量 | 边界暴露外网,风险高 |
| B 逐轮授权 | 仅本轮价 | 实时性差 |
| **C 相对量下沉** | 仅"估值±NBP"+估值快照,不含绝对价/可投量 | **从 C 谈起**,泄露的是策略形状不是绝对价 |

配套:邮件轮询→IMAP IDLE/推送;RPA 轮询→事件驱动;有就发不攒批;指令预热;链路心跳可视化;根本方案换掉邮件通道(网闸 API/消息队列,亚秒级)。

## 4. 数据流

**下行(发起询价)**
```
工作台勾券+选策略+点触发 → 业务层生成 session(策略参数按 C 档打包)
 → 穿透外网 → redroid RPA:chat_session(peer) → 券锚+红线闸 → 双闸门发出
 → 每轮快照留痕
```

**上行(对方回复)**
```
企点收到 → frida hook 拿完整正文(600字截断先拼接)→ 游标去重
 → dify 意图分类+抽取 → L1-L5 归属到 session → 规则引擎决策
 → [下一轮 / 追问量 / 转人工 / 结束] → 转人工则外网 QT 私聊提示交易员 + 工作台高亮
```

**跨日**:会话跨日后"说话前先看一眼"(拉当日估值/报价/可投量,与快照比,按 S2 阈值判续谈/重置/挂起/关闭),**跨日第一条必须人工确认**。

## 5. 复用存款项目(立项按"复用为主")

## 6. 部署环境

- 生产(存款同环境):**鲲鹏 ARM64 + 麒麟 V10 + GaussDB,内网离线**。
  - **利好 redroid**:鲲鹏是 ARM64,企点 arm64 APK **原生跑,不需要 ndk 翻译层**;用 arm64 redroid 镜像。
- 开发/演示(x86 Windows):需 `qtrade-redroid-installer`(redroid 11 + ndk 翻译 + 自定义 binder 内核)。
- 两端共享:企点 APK、设备指纹、frida/adb RPA 脚本、业务层与工作台。
