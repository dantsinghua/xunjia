# P0 测试执行器修复与验收

安琳，2026-10-18 本次范围为 Linux/WSL 测试执行器、统一验证入口和独立故障注入测试。交易规则、Dify 流程及已有未提交改动保持原样。

## 已确认的问题

独立验收对旧 `run_p0.py` 复现了三类失败：组长响应 TERM 后，忽略 TERM 的两个后代仍存活；诊断异常跳过任务清理；BEGIN 记录异常跳过清理且未留下 END。所有探针使用独立合成进程，故障后的兜底清理按进程身份执行，无关哨兵存活。

真实仓库入口另复现两类问题：`tests/conftest.py` 清理应用环境变量时删除 pytest 证据路径；收集阶段取消后仍启动执行阶段。原来两个 180 秒超时的原始栈已丢失，无法追溯具体系统调用或锁，不能把本次确认的缺陷写成它们的历史根因。

## 实现

- `scripts/process_runner.py` 统一管理命令生命周期。子任务使用独立 session 和专用归属标记；通过 PID、PGID、SID、启动时刻及 pidfd 核对身份，TERM 后继续检查全部已识别后代，必要时有界 KILL。诊断失败、取消、BEGIN/结果写入异常均记录明确失败并执行清理。
- `scripts/execution/xunjia_pytest_evidence.py` 记录实际 nodeid 和 setup/call/teardown 结果。插件在导入时保存证据路径，保留应用测试的原有环境与网络隔离。空收集、收集错误、跳过、清单不符或证据缺失均不能通过。
- `tests/run_verification.py` 使用共享执行器。收集失败或取消时记录失败并停止依赖执行；默认证据目录为 `~/.local/state/xunjia-codex/verification`，每次运行创建独立目录，支持 `--output-root`。
- 进度使用文件锁和原子替换；日志禁止覆盖。输入副本、实际输出、事件、命令、计时和结果保存在每次运行目录，`verify_evidence` 可在新进程重新核对摘要。

普通程序退出 0 且不输出内容允许通过；调用者指定预期标记、产物或 pytest 合同时，必须同时满足合同。执行超时保留 124，不以延长预算掩盖失败。执行器要求 Linux `/proc` 与 pidfd；它不是应用生产运行依赖，也不代表麒麟 aarch64 实机部署已经验收。

## 可重复验证

独立测试位于 `tests/execution/`，覆盖监督要求的 T01–T12 共 27 项，以及真实入口、证据缺失、源码漂移、损坏进度、取消与保留 124 的 11 项回归。运行：

```sh
.venv/bin/python -m pytest -q tests/execution --tb=short
```

持久验收通过共享执行器分别收集和执行，核对 nodeid、实际结果、源码前后摘要和无活跃任务残留。详细命令和原始结果保留在本机运行目录的 `P0-CLOSURE.json`，运行文件不进 Git。

原非 Dify 阶段冻结快照另经同版执行器复验：core 283、deployment 83、changed-developer 86，合计 452 个唯一用例，失败及跳过均为 0；每组 90 秒预算，实际执行分别约 34.07、2.93、3.06 秒，源码和执行器无漂移。该 452 是明确范围的冻结复验，不是当前全部脏工作树或真实 Dify 验收。
