安琳明确要求增加双端会话清空与进度对齐，范围为当前选定采集端和企点号的全部会话。

工作台“采集通道”提供“清空并同步全部会话”。确认时固定当前绑定及版本，先停止该范围的旧会话和待执行指令；经现有签封文件中转请求采集端安装新的账号会话版本，等待旧原生调用退出，再返回实际消息进度与屏障。工作台应用并归档旧轮次后，双方确认同一快照；界面只有收到最终确认才显示完成。Windows 采集端账号详情提供只读同步阶段和版本，不再另设发送开关或第二套重置协议。

重置保留历史聊天、报价、原生回执、取消墓碑和去重记录。已实际执行但结果未知的旧指令不改成成功或取消；在旧调用已经退出、新版本屏障生效后，它们作为历史保留，不阻塞新轮次。迟到的旧版本指令不能执行，重置前的预览和模型任务不能写回新轮次。源消息序号与工作台本地修订分别保存，不将“清空”伪装成“已经分析”。

会话作用域必须包含采集端。`xj2_thread` 采用 owner、workbench、account、peer 四元身份。同一个企点号切换采集端后不复用另一台的源消息水位；旧来源无法证明的行保留 NULL，不推测归属。新的明确签封或当前绑定创建新线程时写入采集端身份。原本一名交易员同一券只有一个开放券组、账号容量、用户停止/暂停等业务规则保持。

已有 OceanBase 库使用显式迁移：

- `002_session_reset.sql`：新增会话重置表和命令 `account_epoch DEFAULT 0`。
- `003_thread_workbench.sql`：新增可空采集端来源列，按真实索引列签名识别旧唯一约束，再替换为四元唯一约束。不能猜索引名、重建或清空业务表，也不能用当前绑定自动回填历史来源。
- 新装入口 `001_xunjia_schema_mysql.sql` 与代码生成的完整新 schema 一致。升级前备份 SHOW CREATE、索引和业务数据；重复执行应检查已有列、表、约束。仅有原签封/历史操作证据时才能按明确 thread ID 映射补齐来源。

兼容性：采集端必须在签封目录中声明 `negotiation-v22-session-reset`。首次操作在暂停会话前检查能力；不支持或不可读时明确失败。已有操作使用原 ID、摘要与会话版本继续，不因网络错误再创建一个重置。两端升级应使用同版协议包、宿主和工作台；普通发送、查询及回执继续沿原链路。

验证覆盖真实控制协议的多阶段处理、丢包重试和重启、账号及采集端隔离、旧未决状态、超时原生任务、晚到原文/任务、新消息跨快照、旧预览失效以及界面错误与切换竞态。隔离测试通过不替代现场双方最终确认或真实消息送达。
