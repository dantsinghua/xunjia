# QTrade后台供数与共享配置

## 运行与权限

采集通道页中的QTrade FIX数据源与Innodealing并列，二者独立运行、独立启停。保存不会建立连接；显式开启后，连接由FastAPI应用生命周期持有，浏览器关闭、路由切换或登录令牌过期不停止任务。正常服务关闭保留已开启意图，重启后恢复；用户明确停止则持久化停止意图。网络错误按5/10/30/60秒退避重连，认证拒绝和协议校验失败终止本轮连接并显式报错。仅一个进程可持有同一配置的采集锁。

所有登录用户可查看共享连接状态、编辑停机状态的连接并启停。密码写入0600配置，不回显、不进入localStorage；空密码保留现值，更换FIX登录账号必须提供新密码。保存、启停使用配置摘要进行CAS校验，拒绝过期表单。配置文件、目录及锁文件不允许未经审阅的符号链接。

FIX登录Username、双方CompID及OwnQtNO不是同一个概念，不从姓名或登录用户名猜归属。页面填写的本人QT账号ID只能添加到当前服务端认证用户；既有他人绑定不能被认领、覆盖或移除。原受保护account_owners映射继续有效。机构确需迁移账号归属时，由维护人员停机审阅原映射和历史权限，不能借普通表单静默移交。共用连接不等于共用私聊报价；公共QuoteHub不含QT数据。

## 配置位置

优先使用XUNJIA_QT_CONFIG指定的绝对路径；未指定时使用QB_CONFIG_DIR同级qtrade/connection.json。页面首次完整保存即可创建，无需手工修改真实凭据文件。XUNJIA_STATE_DIR存在时，FIX业务账本位于其qt-fix子目录，否则使用QT配置目录的state/qt-fix。连接端点、登录账号和双方CompID构成独立账本命名空间；换连接不复用其他连接的当前报价，旧账本不删除。

TLS为默认传输，校验服务端证书和主机名，可配置CA及客户端证书/私钥路径；没有关闭验证选项。供应商明确要求专线TCP时，需要显式勾选明文传输确认。中文编码可选UTF-8、GB18030、ASCII；发送时间和业务时间时区可配置。默认心跳60秒、北京时间，依据用户提供V1.0.1手册；实际编码、时区、端点、证书及账号由供应商提供，不预填推测值。

旧journal_path配置仅作为显式兼容模式继续读取，页面显示旧日志供数，不假报FIX在线。停止后保存完整FIX配置会保留旧配置备份，使用独立FIX账本，不覆盖旧日志或旧业务账本。

## 协议范围

依据《腾讯企点QTrade API手册_询价议价接口V1.0.1（FIX）》第4—8页，实现SOH分帧、字节级BodyLength和CheckSum校验、CompID检查、登录A、心跳0、TestRequest1、ResendRequest2、GapFill4及注销5。只接收S/MarketIndicator=4/QuoteType=3的对话报价，下行N/H/Z/S按第9—19页入库。H经济字段按全量快照更新，撤回/过期有独立终态保护；不向对端发送报价、询价、订单、成交或锁量指令。

手册第8页约定重连下行序号重置，第6页登录应答141固定N；此适配器按新连接从1开始校验下行，接受141=N，业务事件以规范化业务字段摘要去重，并在同一SQLite事务中分配跨连接持久序列。会话序号不当作业务唯一键。真实供应商若要求持续会话序号或其他复位语义，须先确认合同再启用，不通过放宽校验兼容未知协议。

序号缺口暂存有界、主动请求补发；缺口未闭合时不宣称报价完整，超时断线重连。相同序号不同内容、错误校验、错误CompID、非GapFill的强制复位均停止接收。重连后，旧记录只有再次被该连接确认后才参与最优价；断线、停机、恢复中仍可查看历史明细，但不将旧记录当成在线最优报价。未映射账号及无效业务报文计入拒收，不展示给其他用户。

## 验证入口与边界

`python -m pytest -q tests/developer/test_qtrade_fix_background.py` 使用独立loopback FIX acceptor，真实TCP字节、合成证书与mTLS、受认证HTTP API和真实SQLite，不连接真实供应商。覆盖分包/粘包、中文、校验拒绝、心跳与超时、重连去重、序号缺口、N/H/Z/S、共享配置CAS、双用户隔离、关闭浏览器会话后继续供数、QT停止不影响Innodealing。

页面测试：`python -m pytest -q web/tests/acceptance/test_qtrade_settings.py`。这些测试不能证明真实供应商认证/网络已通过，不能把Socket在线等同于已收到报价。页面分别显示连接状态、收到、写入、去重和拒收计数。手册不提供单据终态接口，报价不能据此当成可执行交易承诺。
