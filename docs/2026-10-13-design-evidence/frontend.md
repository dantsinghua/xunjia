# 前端最小整改设计（供安琳评审）

安琳，本稿是主整改方案的前端章节素材，不是实施授权或完成报告。依据 `docs/2026-10-13-code-review.md` 的 R01–R40、当前 `web/src` 及本轮已确认裁决；仅只读核对并输出设计，没有修改实现、测试或配置，没有连接真实服务或发消息。

## 1. 已确认范围与收敛结论

- 保留 Vue 3 + ant-design-vue、四个页面 `/quote`、`/monitor`、`/chat`、`/link` 及当前弹窗、表格、三栏、主题。沿用模块级 ref/computed，不引入 Pinia、其他 UI 库、全局事件总线或页面重拆。
- 五人五号、一人一号；默认“我的账号／我的业务”。服务端通过既有 SSO 身份绑定账号，不做跨他人账号选择器、通用角色配置页或新的用户体系。
- 保留**规则内自动谈价**：人工确认批次策略和对象后授权执行；多券可以并行；唯一归属才自动处理，歧义、实价和规则要求的例外转人工。前端不自行计算下一轮价格、不运行另一套会话状态机，不将整改简化为全部人工收发。
- OSS、邮件均本期交付；每绑定选择一种主用通道，人工切换。每条指令冻结通道和绑定版本；结果未知先对账，不能自动改走另一通道补发。
- 主数据及业务持久状态使用与 ibquote 对齐的 OceanBase 方案，前端继续只访问 Python API，不直接访问数据库。后端接口/事务方案由主线整合。
- 停止展示“停止中／已停止”，以执行端确认和服务端状态为准；已送入外部网络的消息不承诺可召回。

采用的最小路线是：修正现有 API 契约、减少页面本地业务状态、补齐真实动作回执；已有组件只做必要的字段、禁用态和失败态修改。各类新鲜度/权限/回执信息在现有顶栏、状态列和弹窗承载。

## 2. 四页功能边界

### 2.1 全局壳和登录

参考现有 ibquote 前端 `web/src/api/client.ts` 与 `App.vue`：SSO 参数进入 `/api/auth/sso`，已有会话用 `/api/auth/me` 校验；请求统一携带既有认证方式，401 回登录门；完成校验后清理地址栏 SSO 参数。保持其已验证的集成方式，不借此另换认证技术栈。**不照搬开发模拟签名页、默认开发口令或校验失败后启用开发登录的回退**。

App 在身份和本人绑定加载成功前不挂载业务页面；登录失败只显示原因和重新从门户进入的入口。顶栏“安琳”改为服务端认证展示名，本人企点登录昵称、稳定号码、主用通道只读显示。门户绑定缺失时提示联系既有配置责任方，不允许前端手填他人账号自绑定。询价会话的浏览器存储命名与 ibquote 分开，除非主线明确采用同一会话体系；登出不误删另一应用凭据。

认证与账号授权始终由服务端执行。页面隐藏按钮只减少误操作，不能替代服务端校验。五个用户相同 peer/code 的记录仍按本人账号隔离。（R01、R06、R09、R33）

**人工确认批次的边界**：确认页展示并冻结选券、收件人、本人绑定、方向/数量、策略、底价及所依赖估值版本。修改任意这些要素即使旧预览失效；再次生成预览、人工确认后才能执行。正常授权后每个规则内回合不重复弹窗；拿到实价转人工，不自动成交。调整在谈会话底价仍需独立确认变更，不能通过全局策略保存悄悄影响它。

首句正文由结构化参数产生并展示于现有预览区。建议本期将“开始自动询价”里的自由文本编辑收敛为参数编辑后重新生成预览；若必须保留首句文本编辑，则编辑后必须回服务端解析/预检并使原预览失效，无法核对参数时不能启动自动会话。普通人工措辞仍可在监控输入框发送，经同一红线闸。此项是供评审的局部减法，不删除人工发送能力。

### 2.4 智能问答 `/chat`

保留页面、输入、快捷问题、文本回答和既有 Chart 组件；只使用当前本人有权读取的数据。真实后端未提供的回答来源/图表不使用规则样例伪装查询结果。禁用原始 HTML 或可靠净化最终 Markdown HTML，链接仅允许规定安全协议；不新增问答平台或长会话存储。（R01、R14、R24）

固定 CONVS 不再冒充“历史会话”：本期删除该演示列表或明确改作推荐问题。没有真实源定位时删除“一键溯源”“数字均可溯源”的文案；不为保住这两句话新增一套检索/溯源系统。已有本次会话可继续在当前页面内存显示，离开后不宣称能恢复。（R14、R33；评审“功能完成度边界”）

### 2.5 采集通道 `/link`

保留本人账号的 OSS/邮件配置、保存、只读当前绑定、测试步骤及行情源健康。账号固定为 SSO 绑定号码；通道配置不构成重新选择他人企点号的入口。接入配置权限由后端给定，没有该权限时只读显示，不新增权限管理界面。（R01、R06、R20、R31、R40）

两种表单都按同一“保存配置→测试当前版本→人工设为主用”的流程。测试必须区分配置有效、账户在线、入站通、出站/ACK 通；凭据输入留空表示不改，已保存只显示设置状态。结果区与表单填充解耦，失败原因不在刷新后清掉；测试一个坏绑定不能踢掉健康主通道。（R20、R31、R40）

主用通道切换前显示本人未决命令数；有 unknown 时进入对账，不能将原命令复制到新通道。人工切换仅影响新批次；已有批次继续使用已确认的绑定版本，若原通道不可用则停在等待处理/明确失败，不暗中迁移。通道健康周期读取并标最后成功时点，断线保留内容且禁用受影响的新发送。（R06–R08、R18、R20、R38）

业务页面不展示 OSS 密钥、对象名和传输调试细节。是否保留低层连接表单由部署配置责任方决定，普通交易员只看昵称、号码、主通道和健康结果；不增加“专家模式”作为第三套通道配置体系。

## 3. 一套真值、最少状态

| 数据 | 唯一权威来源 | 前端允许保留的内容 | 要删的并行真值 |
|---|---|---|---|
| 用户与本人账号/通道绑定 | SSO + 后端绑定记录及版本 | 已验证 viewer/binding 的只读缓存 | 任意全局 active 账号、可编辑备注当绑定键 |
| 债券身份 | 后端主数据的标准 code（市场代码含后缀） | 同一个 code 在列表、选择、路由、上下文中贯穿 | name 当键；windcode 与 bondUniCode 混入同一选择集 |
| 行情 | 后端同源快照与增量，带版本/交易日/时间 | 当前页的数据镜像、刷新代次 | 前端生成最优报价、固定时间、随机成交 |
| 筛选与选择 | FilterSpec + 后端解析的确认批次 | 输入草稿、应用后的 FilterSpec、ID 选择/排除 | rows/bonds 两套命中集，各按钮自行算范围 |
| 底价和策略 | 已校验版本化后端记录 | 未保存表单草稿；成功响应后刷新 | floorKind/floorValue/bpOverride 作为长期权威 |
| 谈价状态/逐收件人发送状态 | 服务端 session/command/receipt 查询 | “请求处理中”的短暂 UI 状态 | 永久 stOverride、用 stage 固定档位编造进度 |
| 聊天与审计 | 有 message_id/cmd_id 的服务端事件 | 未提交输入草稿、在途请求关联信息 | 拼接 extraMsgs 作为第二份历史、按数组下标造 ID |

`bondUniCode/u` 是行情源键，只在 API/行情接入边界转换为标准 code；前端不能有的接口按 u、有的按 code 解释同一 except。若 OceanBase 对外既定主键不是 code，主线可在 DTO 中映射稳定业务键，但所有页面必须只使用这一种键，不能同时暴露两种选择语义。（R06、R07、R11、R12、R14、R19、R34、R37、R39）

### 3.1 选择、分页与行情

FilterSpec 至少涵盖渠道/经纪商、关键字、券种/期限/清算、报价类型/标签、价格/偏离/量区间、当前状态。方案名若没有持久定义则禁用，不能把一个未定义字符串当有效业务筛选。

表格和“全选匹配结果”都把同一 FilterSpec 交后端。改变已应用筛选/渠道时清空选择，并清楚提示原选择已清空；同一筛选内翻页保持选择。开始、停止、底价变更共用这一选择描述，在服务端确认批次阶段解析为具体对象，返回真实数量和可分页核对的清单。确认后固定对象集，行情变化不把新出现的券偷偷加入已授权批次。（R12、R36）

建议把现有无限追加改为**有明确上一页/下一页的服务端分页**，保留表格和侧栏，只修改底部翻页区。当前页 50 行；选择跨页独立保存。这样删除“2000 行裁剪+持续前进游标”的矛盾，无需实现双向无限窗口缓存。游标及排序由后端定义，前端不自行重排；搜索能直达后页券。（R12、R30）

保留现有 worker/500ms pull 传输；当前已调用的合并函数作为唯一增量入口，正确解释“缺字段=不变、null=清空、撤销标识=移除报价有效性”，更新 fm/cl/报价时间/交易日。不额外保留无人调用的 RowStore。与当前动态筛选有关的属性变化后，合并安排一次受限频率的当前范围快照刷新，使行成员和数量由后端收敛，不在浏览器维护另一套权威 FilterSpec 判断。（R25、R27、R29、R34）

单经纪商先沿用 scoped REST 定时刷新，沿当前页监控频率配置并显示更新时间；不扩大成第二套 WS 协议。其他渠道仍用现有推送；不能将全市场最优增量写入某家经纪商页面。读取必须校验完整范围键与 generation，旧响应无权改数据、loading 或错误态。断流/重连后重新取当前范围快照。（R28、R35、R36、R38）

### 3.2 状态与重试

谈价状态与传输状态分开显示：

- 谈价：待人工确认 → 询价中 → 转人工／停止中 → 已停止／已结束；具体后端枚举由规则服务确定，页面只映射。
- 传输：提交中 → 已提交/待回执 → 已送达；等待超时进入结果未知，不直接伪造明确失败；明确失败展示原因。
- 无实际成交授权/结果，前端不得生成“已成交”。实价转人工不是成交成功；消息已送达也不是实价。
- 网络超时后以同一业务请求 ID 查询结果；同 key 不同内容为冲突，不自动重发。部分成功保留已送达目标，仅对明确失败目标重新确认重试。
- 多用户或双标签修改同一配置/会话时附 expected_version；冲突提示重新加载确认，不做前端最后写入覆盖。

服务端版本优先。页面只在请求期间禁用对应动作，收到成功 DTO 后替换视图；没有可以无限遮住服务端的乐观“已停止／已保存／询价中”。（R02、R05–R10、R15、R16、R19）

## 4. 接口最小改造边界

保留现有 `/api` 路径组织和 `{ok,data,hint}` 基本返回，不新增 BFF、GraphQL、通用配置中心或消息总线。下面为前端所需字段/语义，后端最终路径由主线统一，避免为了每个 R 编号增一套接口。

| 接口组 | 最小变更 | 关联 |
|---|---|---|
| `/api/auth/sso`、`/api/auth/me` | 参考 ibquote 接入；me 或本人绑定查询给出身份、本人账号、绑定版本、当前主通道 | R01、R06、R33 |
| `/api/bonds`、详情、现有 WS | 全量 FilterSpec、准确 total、可恢复分页游标、版本/交易日/时间、明确撤价；详情直接返回真实数据 | R12、R14、R25–R30、R35、R36 |
| `/api/strategy` 与底价查询/保存 | DTO 双向映射；统一类型、方向、版本；成功返回保存值；读取可恢复底价 | R11、R16、R19、R22 |
| RFQ 预览 + 既有 `/api/im/rfq/send` | 只新增一个必要的批次预览入口；解析选择和逐收件人正文，返回批次 ID/版本及明细；确认发送引用该预览而非重算当前页面值 | R04、R06–R08、R12、R21 |
| `/api/rfq/stop`、接管/恢复 | 接到真实会话；设置明确目标状态，返回请求/会话版本及停止中/已停止 | R02、R05、R15、R19 |
| 现有 monitor summary/counterparties/chat | GET 纯查询、本人作用域、聊天游标、message_id；错误不是成功空结果 | R03、R10、R13、R18、R32、R37–R39 |
| `/api/im/rfq/status`、receipts | 按批次/会话/command 查询逐目标结果；足够让刷新和重启恢复；删除不等于停止，未需要的 DELETE 入口先撤掉 | R07、R08、R10、R19 |
