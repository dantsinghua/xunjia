# 实时行情管线契约 v1（照 DM 成熟做法改造）

> 2026-09-19。依据对 DM(web.innodealing.com) quote-web 生产 bundle 的逆向分析。
> 三方并行实现的唯一口径：**库表 / 生产端 / 网关 / SharedWorker / 主线程**。改动前先改本文。

## 0. 为什么是这个形状

事故背景：800 行全量 DOM + 每条 WS 一次渲染 → 渲染进程 130% CPU / 800MB。
DM 的做法（已证实）：

1. 服务端成批，protobuf+zlib，一条长连接多路复用
2. 浏览器端 **SharedWorker** 持连接，跨标签共享
3. **主线程每 500ms 主动 pull**，worker 把窗口内消息按组聚合一次性回
4. 逐行 `flowId` 单调版本号，last-write-wins，240s 过期
5. 推送只带动态字段，静态列从 worker 缓存 join
6. 筛选 = 订阅组粒度，前端不做全量过滤

本文把 1–6 落成我们自己的契约。**不照抄 protobuf**（我们量级下 JSON+gzip 足够，且省一个编译步骤），其余照搬。

## 1. 库表（SQLite，mock 侧；生产替换为 MySQL 同构）

### 1.1 `bond_static` —— 静态主数据，只读，worker 缓存它
```sql
CREATE TABLE bond_static (
  bond_uni_code TEXT PRIMARY KEY,      -- 关联键,推送里只带这个
  windcode TEXT NOT NULL,
  sec_name TEXT NOT NULL,
  bond_type TEXT, residual_maturity TEXT, residual_days INTEGER,
  coupon REAL, bond_rating TEXT, issuer_rating TEXT, implied_rating TEXT,
  issuer TEXT, nature TEXT, industry TEXT, prov TEXT,
  is_public INTEGER, is_guaranteed INTEGER, is_subordinated INTEGER,
  is_perpetual INTEGER, is_udic INTEGER, embedded_option TEXT,
  tags TEXT,                            -- JSON 数组
  val_yield REAL, net_price REAL, mod_dur REAL, val_date TEXT
);
CREATE INDEX idx_static_type   ON bond_static(bond_type);
CREATE INDEX idx_static_rating ON bond_static(bond_rating);
CREATE INDEX idx_static_prov   ON bond_static(prov);
```

### 1.2 `quote_flow` —— 报价流水，**每条一个 flow_id**
```sql
CREATE TABLE quote_flow (
  flow_id INTEGER PRIMARY KEY AUTOINCREMENT,  -- 单调递增,全局唯一,就是行版本号
  bond_uni_code TEXT NOT NULL,
  group_name TEXT NOT NULL,                   -- 订阅组,见 §3
  issue_time INTEGER NOT NULL,                -- 服务端产生时间(ms)
  -- 动态字段(推送只带这些)
  best_bid REAL, best_bid_vol INTEGER, best_bid_side TEXT,
  best_ofr REAL, best_ofr_vol INTEGER, best_ofr_side TEXT,
  firmness TEXT, clearing TEXT, status TEXT,
  ib REAL, ibv INTEGER, io REAL, iov INTEGER   -- 内部意向底价/量
);
CREATE INDEX idx_flow_group ON quote_flow(group_name, flow_id DESC);
CREATE INDEX idx_flow_bond  ON quote_flow(bond_uni_code, flow_id DESC);
```

**行身份 = `bond_uni_code`，行版本 = `flow_id`。** 同一只券的新报价是**同 key 新版本**，不是新行。这条是整个改造的地基：没有它，成批会重复、静态 join 无锚、订阅切换会错乱。

### 1.3 `quote_latest` —— 每券最新一条的物化视图（列表首屏走它）
```sql
CREATE TABLE quote_latest (
  bond_uni_code TEXT PRIMARY KEY,
  flow_id INTEGER NOT NULL,
  group_name TEXT NOT NULL, issue_time INTEGER NOT NULL,
  best_bid REAL, best_bid_vol INTEGER, best_bid_side TEXT,
  best_ofr REAL, best_ofr_vol INTEGER, best_ofr_side TEXT,
  firmness TEXT, clearing TEXT, status TEXT,
  ib REAL, ibv INTEGER, io REAL, iov INTEGER
);
CREATE INDEX idx_latest_group ON quote_latest(group_name, flow_id DESC);
```
写流水时 upsert 本表（`ON CONFLICT(bond_uni_code) DO UPDATE ... WHERE excluded.flow_id > quote_latest.flow_id`）。

## 2. 消息协议（JSON，网关侧 permessage-deflate 压缩）

### 2.1 主线程 ↔ SharedWorker
沿用 DM 的类型枚举语义，精简到我们需要的：
```ts
type WorkerMsgType =
  | 'INIT_CONNECTIONS'    // main→worker 首次建连,带 identifiers
  | 'JOIN_GROUP'          // main→worker 订阅组(差集)
  | 'LEAVE_GROUP'         // main→worker 退订(引用计数归零才发)
  | 'PULL'                // main→worker 每 500ms 拉一次,带 requestTime
  | 'BATCH'               // worker→main 窗口内聚合结果
  | 'CACHE_REQUEST'       // main→worker 要静态信息
  | 'CACHE_RESPONSE'
  | 'STAT'                // worker→main 埋点
  | 'OPEN' | 'CLOSE' | 'ERROR'
```

**PULL 响应体（worker→main）**——照 DM，按组聚合成 Map：
```ts
{ type: 'BATCH',
  requestTime: number,          // 回传 main 发起时刻,用于算 worker→main 延迟
  workerSendTime: number,
  notification: Map<string, QuoteDelta[]>,   // groupName -> 该窗口内的增量
  dropped: number }             // 因背压丢弃的条数(见 §4)
```

### 2.2 网关 ↔ worker（wss）
```ts
// worker→gateway
{ op: 'sub',   groups: string[] }
{ op: 'unsub', groups: string[] }
{ op: 'ping' }

// gateway→worker,服务端成批
{ op: 'batch', group: string, sendTime: number, items: QuoteDelta[] }
{ op: 'pong' }
```

**`QuoteDelta` —— 只有动态字段**：
```ts
interface QuoteDelta {
  f: number      // flow_id  ← 行版本
  u: string      // bond_uni_code ← 行身份
  t: number      // issue_time
  bb?: number; bbv?: number; bbs?: string   // best bid / vol / side
  bo?: number; bov?: number; bos?: string   // best ofr / vol / side
  fm?: string; cl?: string; st?: string     // firmness / clearing / status
  ib?: number; ibv?: number; io?: number; iov?: number
}
```
字段名缩写不是为了炫技：几十万条/天，`best_bid_vol` → `bbv` 每条省 ~60 字节，一天省几十 MB 传输。

### 2.3 静态信息缓存
```
GET /api/bond-static?codes=a,b,c      → { ok, data: BondStatic[] }
GET /api/bond-static/all              → 全量,worker 启动时拉一次,存 IndexedDB
```
worker 持有 `Map<bond_uni_code, BondStatic>`；主线程收到 delta 后 `Object.assign({}, static, delta)` 拼成完整行（DM 的 `buildBondData` 就是这么做的）。

## 3. 订阅组（筛选 = 订阅粒度）

组名规则：`bond-{维度}_{值}`，与 DM 的 `split("-")[0]` 取网关前缀兼容。

| 组名 | 含义 |
|---|---|
| `bond-all` | 全量（默认） |
| `bond-type_{中票\|短融\|PPN\|ABS\|地方债\|公司债}` | 按券种 |
| `bond-rating_{AAA\|AA+\|AA\|AA-}` | 按债项评级 |
| `bond-tenor_{lt1\|1to3\|3to5\|5to7\|7to10\|gt10}` | 按剩余期限 |
| `bond-clearing_{T0\|T1\|TN}` | 按清算 |
| `bond-prov_{江苏\|山东\|...}` | 按区域 |

前端筛选条件 → 映射成组名集合 → `JOIN_GROUP` 差集 / `LEAVE_GROUP`。
**服务端只推已订阅组，前端不再做任何全量过滤。**

首屏与翻页仍走 REST keyset 游标（`GET /api/bonds?before=&limit=&groups=`），
与推送用 `flow_id` 统一收敛（REST 来的行无 `pushLocalTime`，同 flow_id 时 REST 胜——照 DM）。

## 4. 背压与合流（必须实现，不是可选）

1. **网关侧**：每组每 200ms 成批发一次；同一 `bond_uni_code` 在窗口内只保留最大 `flow_id`（服务端就去重，别把重复推给客户端）。
2. **worker 侧**：收到批后按组累积；同 `bond_uni_code` 覆盖。窗口上限 `MAX_PENDING_PER_GROUP = 5000`，超出丢最旧并累加 `dropped`。
3. **主线程侧**：500ms pull 一次；标签页 `document.hidden` 时**停止 pull**（这是 DM 后台标签零消耗的关键）；恢复时先拉一次。
4. **渲染侧**：拿到批后走 upsert，只对真正变化的行打 `blink` class。

## 5. 客户端行状态收敛

```ts
// 照 DM 的 getUniquePushData
const EXPIRE_MS = 240_000
rows: Map<string /*bond_uni_code*/, Row>
function upsert(incoming: QuoteDelta[]) {
  for (const d of incoming) {
    const cur = rows.get(d.u)
    if (!cur || d.f >= cur.f) rows.set(d.u, merge(cur, d))   // last-write-wins
  }
  // 丢弃 now - pushLocalTime > EXPIRE_MS 的行
}
```

## 6. 埋点（改造前先加，否则无法验证收益）

| 指标 | 采集点 | 告警阈值 |
|---|---|---|
| `worker→main 延迟` | `BATCH.workerSendTime - requestTime` | >2s |
| `批量条数` | `Σ notification.values().length` | — |
| `分发耗时` | upsert+render 前后 `performance.now()` | >1s |
| `dropped` | worker 背压丢弃累计 | >0 即告警 |
| `渲染行数` | 虚拟窗口内行数 | 应恒定 |

## 7. SharedWorker 降级

目标环境可能有国产化浏览器不支持 `SharedWorker`。**必须实现三级降级**：
1. `SharedWorker` —— 跨标签共享一条连接（首选）
2. `Worker`（专用）—— 每标签一条连接，但 WS 仍不占主线程
3. 主线程直连 WS —— 最后兜底，保留 500ms pull 语义（改为内部缓冲队列）

三级对主线程暴露**同一套 API**，业务代码不感知。
